## Step 2: Launcher Dependency Grouping

The second optimization step changes only `ModTheSpire2Launcher.exe`.

- Rebuilt source: `NativeLauncher/ModTheSpire2Launcher.c`
- `ModTheSpire2.dll` remains the Step 1 copy-button build.
- Startup flow was kept close to the `3747911678` baseline: no `steam://rungameid` fallback and no direct `CreateProcessW` game launch branch.

Added launcher behavior:

- Reads mod `dependencies` from each mod JSON.
- Supports both object dependencies such as `{ "id": "BaseLib" }` and simple string dependencies such as `"BaseLib"`.
- Sorts known dependency children directly under their known dependency.
- Indents dependent mods in the list.
- Prevents checking a dependent mod unless its known dependency is checked first.
- Unchecking a dependency recursively unchecks mods that depend on it.
- Performs a second validation before launch, so stale settings cannot launch an invalid dependency selection.

### Step 2 Fix

The first dependency build could fail before launching because `SortModsByDependencies` allocated a large `ModInfo sorted[MAX_MODS]` array on the stack. `ModInfo` is large, so this could overflow the Win32 stack during launcher refresh.

Fixes applied:

- Moved dependency sort scratch arrays to `HeapAlloc`.
- Tightened dependency parsing so `{ "id": "BaseLib", "min_version": "..." }` only records `BaseLib`, not `min_version` or the version string.
- Added diagnostic output for dependency depth and dependencies.
